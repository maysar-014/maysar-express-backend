# AUTHENTICATION MIGRATION PLAN: CATALOG SERVICE → AUTH SERVICE
## Comprehensive Migration Strategy

### EXECUTIVE SUMMARY

This document outlines the complete migration of all authentication and authorization features from the catalog service to the centralized auth service. The migration will ensure security, maintainability, and consistency across the microservices architecture.

### CURRENT STATE ANALYSIS

#### Catalog Service Authentication Implementation
- **Location**: `catalog-service/src/api/middleware/authentication.middleware.ts`
- **Authorization**: `catalog-service/src/api/middleware/authorization.middleware.ts`
- **Features**: JWT validation, role-based access, permission checking, device tracking, brute force protection
- **Integration**: Embedded directly in catalog service routes and controllers

#### Auth Service Current State
- **Location**: `auth-service/src/api/controllers/auth.controller.ts`
- **Features**: Basic login/logout, session management, 2FA support
- **Architecture**: Service-oriented with use cases and domain engines
- **Missing**: Middleware layer, comprehensive authorization, API integration endpoints

### TECHNICAL IMPLEMENTATION DETAILS

#### 1. Middleware Architecture
```typescript
// Auth Service Middleware Structure
export interface AuthMiddlewareConfig {
  jwtSecret: string;
  tokenExpiration: number;
  enableBruteForceProtection: boolean;
  enableDeviceTracking: boolean;
  enablePermissionCaching: boolean;
}

export class AuthenticationMiddleware {
  constructor(private config: AuthMiddlewareConfig) {}
  
  authenticate(): RequestHandler {
    return async (req, res, next) => {
      // Call auth service API for token validation
      const result = await this.authService.validateToken(req.headers.authorization);
      if (result.valid) {
        req.user = result.userContext;
        next();
      } else {
        res.status(401).json({ error: 'Invalid token' });
      }
    };
  }
}
```

#### 2. Service Discovery Integration
```typescript
// Service Discovery Client
export class AuthServiceClient {
  private baseUrl: string;
  
  constructor() {
    this.baseUrl = process.env.AUTH_SERVICE_URL || 'http://auth-service:3001';
  }
  
  async validateToken(token: string): Promise<TokenValidationResult> {
    const response = await fetch(`${this.baseUrl}/api/v1/auth/validate-token`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ token })
    });
    return response.json();
  }
}
```

#### 3. Configuration Management
```typescript
// Auth Configuration
export const authConfig = {
  jwt: {
    secret: process.env.JWT_SECRET!,
    algorithm: 'HS256' as const,
    expiration: parseInt(process.env.JWT_EXPIRATION || '900000'), // 15 minutes
  },
  security: {
    enableBruteForceProtection: process.env.ENABLE_BRUTE_FORCE === 'true',
    maxAttempts: parseInt(process.env.MAX_LOGIN_ATTEMPTS || '5'),
    lockoutTime: parseInt(process.env.LOCKOUT_TIME || '900000'), // 15 minutes
  },
  middleware: {
    enableDeviceTracking: process.env.ENABLE_DEVICE_TRACKING === 'true',
    enablePermissionCaching: process.env.ENABLE_PERMISSION_CACHING === 'true',
    cacheExpiration: parseInt(process.env.CACHE_EXPIRATION || '300000'), // 5 minutes
  }
};
```

#### 4. Error Handling Strategy
```typescript
// Centralized Error Handling
export class AuthError extends Error {
  constructor(
    public code: string,
    public message: string,
    public statusCode: number = 401
  ) {
    super(message);
  }
}

export const authErrorHandler = (error: AuthError, req: Request, res: Response, next: NextFunction) => {
  logger.error('Auth error', { error: error.message, code: error.code });
  
  res.status(error.statusCode).json({
    success: false,
    error: {
      code: error.code,
      message: error.message
    }
  });
};
```
