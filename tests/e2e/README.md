# End-to-End (E2E) Tests

This folder contains live API smoke tests and property-based helper tests that exercise
the running platform against the flow docs in `docs/Flow Docs/`.

The live suite is intentionally opt-in — it only runs when the backend is up and seeded
with the shared test users from `docs/test-users.md`, generated by the live auth/register flow.

---

## Running the suite

```bash
# Run all live E2E tests (requires running backend)
npm run test:e2e:live

# Run only P0 deploy-gate tests
cross-env RUN_LIVE_E2E=true jest --selectProjects=e2e --runInBand --testNamePattern='\[P0\]'

# Run P1 daily CI tests
cross-env RUN_LIVE_E2E=true jest --selectProjects=e2e --runInBand --testNamePattern='\[P1\]'

# Run P2 weekly CI tests
cross-env RUN_LIVE_E2E=true jest --selectProjects=e2e --runInBand --testNamePattern='\[P2\]'

# Run property-based helper tests only (NO backend required)
jest --selectProjects=e2e --testPathPattern=helpers.e2e
```

### Environment variables

| Variable | Default | Purpose |
|----------|---------|---------|
| `RUN_LIVE_E2E` | — | Set to `true` / `1` / `yes` to enable live tests |
| `E2E_BASE_URL` | `http://localhost:3000` | Platform base URL (highest priority) |
| `PLATFORM_BASE_URL` | — | Fallback base URL |
| `BASE_URL` | — | Fallback base URL (also used by the safety gate) |

## Shared fixtures and helpers

### `fixtures/seeded-users.ts`

Single source of truth for all seeded test user IDs, emails, and passwords.

```typescript
import { SEEDED_USERS, WALLET_TOP_UP_MINIMUM } from './fixtures/seeded-users';
const buyer = SEEDED_USERS.buyer; // { role, email, password, id }
```

### `helpers/live-api.ts` — exports

| Export | Purpose |
|--------|---------|
| `requestJson(path, init?)` | Fetch-based helper; returns `{ status, ok, body, text }` |
| `extractAccessToken(body)` | Pulls `accessToken` from login response body |
| `asRecord(value)` | Casts `unknown` to `Record<string, unknown>` |
| `resolveLiveBaseUrl()` | Returns base URL (trailing slashes stripped) |
| `liveTestSuite` | `describe` when `RUN_LIVE_E2E=true`, `describe.skip` otherwise |
| `loginAs(user)` | Logs in as a seeded user, returns `accessToken` |
| `getAdminToken()` | Returns a cached admin token |
| `clearAdminTokenCache()` | Invalidates the admin token cache |
| `ensureWalletMinimum(userId, min, adminToken)` | Idempotent wallet top-up |
| `authHeader(token)` | Returns `{ authorization: 'Bearer <token>' }` |
| `assertOk(response, context?)` | Throws descriptive error if not 2xx |
| `extractWalletBalance(body)` | Extracts numeric balance from wallet response |

## Truly deferred flows

These require external infrastructure or multi-step sagas not achievable with seeded data alone:

| Flow | Reason deferred |
|------|----------------|
| AUTH-03 (password reset) | Requires real email delivery or SMS OTP bypass |
| AUTH-04 (2FA setup) | Requires TOTP device or SMS provider in test mode |
| SEL-04/SEL-05 (campaigns) | Requires seeded campaign + pricing engine data |
| ENA-02 full attribution chain | Requires referral link → buyer order → delivery → auto-commission via event bus |
| SEL-12 (enabler collaboration) | Requires enabler + seller co-operative seeding |

## Safety gate

All test runs pass through `tests/global-setup.js` which validates that no
production-like credentials are present before any HTTP request is made.

Copy `.env.test.example` to `.env.test` and use only test/sandbox values.
